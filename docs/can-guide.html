STM32F407 CAN1: a practical bxCAN guide

A self-contained, register-level recipe for the STM32F407 CAN1 peripheral: hardware, pin muxing, timing, transmit, filtered receive, interrupts, debugging, and the USB-CAN tools in this repository.

Scope. This guide is for classic CAN (up to 8 data bytes) on the STM32F407 bxCAN controller. It uses CAN1, PB8/PB9, a 16 MHz APB1 clock, 500 kbit/s, periodic ID 0x123 transmission, and filtered ID 0x321 reception. It does not apply to FDCAN peripherals or CAN FD.

1. The mental model

CAN is a shared, differential bus. The STM32 controller creates and consumes the digital CAN_TX/CAN_RX signals; it cannot drive CANH/CANL directly. A CAN transceiver converts those logic pins to the physical bus. Every node must use the same bitrate. A correctly received frame is acknowledged by at least one other active node.

LayerSTM32F407 itemJob
ApplicationTasks / your codeDecides which ID and bytes to send; consumes a received snapshot.
ControllerCAN1 / bxCANArbitration, CRC, ACK check, filters, three TX mailboxes, two RX FIFOs.
MCU pinsPB9 TX, PB8 RX3.3 V digital signals between controller and transceiver.
Physical busTransceiver, CANH, CANLDifferential electrical signaling and bus termination.
Do not connect CANH/CANL to PB8/PB9. PB8/PB9 connect to the transceiver’s logic-side RXD/TXD pins. The analyzer may observe PB9 as a digital signal, but use a proper CAN interface/transceiver to observe CANH/CANL.

2. Hardware that must work first

  1. Connect PB9 → transceiver TXD input and PB8 ← transceiver RXD output. Check the names on the transceiver data sheet: names are often from the transceiver’s point of view.
  2. Power the transceiver at a voltage compatible with its logic pins. Use a 3.3 V-compatible part, or a verified level-compatible interface.
  3. Join MCU and transceiver ground.
  4. Connect CANH to CANH and CANL to CANL. A bus needs two active nodes for normal communication.
  5. Fit 120 Ω between CANH and CANL at each physical end of the bus, not at every node.
  6. Ensure the transceiver is not in standby/silent/shutdown mode.

PB9 is normally recessive high and drives low for a dominant CAN bit. PB8 is an input; it only changes when the transceiver drives RXD. A logic analyzer alone cannot acknowledge a frame, so it cannot make an isolated transmitter produce a valid, ACKed bus frame.

3. Enable CAN1 on PB8/PB9

On this STM32F407 package, PB8 is CAN1_RX and PB9 is CAN1_TX when each pin selects alternate function 9 (AF9). The GPIO configuration has four parts:

              |  ((9U << 0) | (9U << 4));

4. Start bxCAN in the correct state

CAN1 is on APB1. The controller starts asleep and configuration-protects key registers outside initialization mode. Follow this order every time:

RCC->APB1ENR  |= RCC_APB1ENR_CAN1EN;      // enable peripheral clock
RCC->APB1RSTR |= RCC_APB1RSTR_CAN1RST;    // known reset state
RCC->APB1RSTR &= ~RCC_APB1RSTR_CAN1RST;

CAN1->MCR &= ~CAN_MCR_SLEEP;              // wake controller
while (CAN1->MSR & CAN_MSR_SLAK) { }

CAN1->MCR |= CAN_MCR_INRQ;                 // enter init mode
while (!(CAN1->MSR & CAN_MSR_INAK)) { }

/* configure BTR, filters and MCR options here */

CAN1->MCR &= ~CAN_MCR_INRQ;                // enter normal mode
while (CAN1->MSR & CAN_MSR_INAK) { }

MSR.SLAK and MSR.INAK are hardware acknowledgements. Always wait for them; merely changing MCR does not prove the mode transition finished.

5. Compute the exact bit timing

The CAN clock is PCLK1. With the reset clock configuration used in this project, PCLK1 is 16 MHz. One CAN bit is:

bitrate = PCLK1 / (prescaler × (1 + time-segment-1 + time-segment-2))

The bxCAN BTR fields store each quantity minus one. The synchronisation segment is always one time quantum (TQ).

BTR fieldStored valueActual valueCurrent 500 kbit/s setup
BRP[9:0]prescaler − 1CAN clock prescaler1 → prescaler 2
TS1[3:0]segment 1 − 1propagation + phase segment 112 → 13 TQ
TS2[2:0]segment 2 − 1phase segment 21 → 2 TQ
SJW[1:0]SJW − 1maximum resynchronisation adjustment0 → 1 TQ
// 16 MHz / (2 × (1 + 13 + 2)) = 500,000 bit/s; sample point 87.5%
CAN1->BTR = (1U << CAN_BTR_BRP_Pos)
          | (12U << CAN_BTR_TS1_Pos)
          | (1U << CAN_BTR_TS2_Pos);
Desired bitrate, PCLK1=16 MHzBRP fieldTS1 fieldTS2 fieldResult

500 kbit/s112116 MHz / (2 × 16)

If you later configure the PLL or APB1 prescaler, PCLK1 may no longer be 16 MHz. Recalculate BTR; do not reuse the numbers blindly.

6. Send a classic CAN data frame

bxCAN has three transmit mailboxes. This project uses mailbox 0. A mailbox is available when TSR.TME0=1. Standard IDs occupy bits 31:21 of TIR; data bytes 0–3 go into TDLR and 4–7 into TDHR, least-significant byte first.

RegisterWhat to writeCritical detail
TI0RSTID << 21, IDE=0, RTR=0Write it initially with TXRQ clear.
TDTRDLC in bits 3:0Classic CAN allows 0–8.
TDLR, TDHRPayload wordsLoad all bytes before requesting TX.
TI0R.TXRQset to 1Must be the final write. It starts transmission immediately.
if (CAN1->TSR & CAN_TSR_TME0) {
    CAN1->sTxMailBox[0].TIR  = 0x123U << CAN_TI0R_STID_Pos;
    CAN1->sTxMailBox[0].TDTR = 8U;
    CAN1->sTxMailBox[0].TDLR = 0x40302010U; // bytes: 10 20 30 40
    CAN1->sTxMailBox[0].TDHR = 0x80706050U; // bytes: 50 60 70 80
    CAN1->sTxMailBox[0].TIR |= CAN_TI0R_TXRQ;
}

After completion, inspect TSR.RQCP0, TSR.TXOK0, TSR.ALST0, and TSR.TERR0. The current demo sets MCR.NART: one failed attempt (for example, no ACK) completes rather than retrying continuously. This is helpful for a logic-analyzer test. On a real network, remove NART if normal CAN automatic retransmission is wanted. MCR.ABOM automatically recovers from bus-off.

7. Receive only ID 0x321

Filtering occurs before a frame enters FIFO0/FIFO1. This is the correct place to reject unwanted traffic. Filter registers are shared by CAN1 and CAN2; FMR.CAN2SB=14 assigns banks 0–13 to CAN1. The project uses bank 0 in 32-bit identifier-mask mode.

Filter settingValueWhy
FMR.FINIT1 while configuringFilter configuration is only safe in filter init mode.
FA1R.FACT00, then 1Disable bank 0 before edits; enable it when done.
FM1R.FBM00Select identifier-mask mode, not list mode.
FS1R.FSC01Select one 32-bit filter pair.
FFA1R.FFA00Route accepted frames to FIFO0.
FR10x321 << 21The expected standard ID in the RIR layout.
FR20xFFE00000 | IDE | RTRMask: compare all 11 ID bits, IDE, and RTR.
CAN1->FMR |= CAN_FMR_FINIT;
CAN1->FA1R &= ~CAN_FA1R_FACT0;
CAN1->FM1R &= ~CAN_FM1R_FBM0;        // mask mode
CAN1->FS1R |= CAN_FS1R_FSC0;          // 32-bit scale
CAN1->FFA1R &= ~CAN_FFA1R_FFA0;       // FIFO0
CAN1->sFilterRegister[0].FR1 = 0x321U << CAN_RI0R_STID_Pos;
CAN1->sFilterRegister[0].FR2 = CAN_RI0R_STID_Msk | CAN_RI0R_IDE | CAN_RI0R_RTR;
CAN1->FA1R |= CAN_FA1R_FACT0;
CAN1->FMR &= ~CAN_FMR_FINIT;

In mask mode, a one in FR2 means “compare this bit”; a zero means “do not care.” To accept any standard data frame, set FR1 to zero and make FR2 equal CAN_RI0R_IDE | CAN_RI0R_RTR. To accept multiple exact IDs, use list mode or more banks.

8. Drain FIFO0 and store the latest frame

FIFO0 contains only frames accepted by the filter. RF0R.FMP0 is the number of pending entries (0–3). Read the four mailbox registers first, then write RF0R.RFOM0=1 to release that entry. Releasing before reading discards the data.

Receive mailbox registerMeaning
RIRIdentifier. For a standard frame, ID = (RIR & STID_Msk) >> 21. IDE tells standard versus extended; RTR tells data versus remote.
RDTRDLC in bits 3:0, timestamp in higher bits when enabled.
RDLRData bytes 0, 1, 2, 3 in byte lanes 0, 1, 2, 3.
RDHRData bytes 4, 5, 6, 7 in byte lanes 0, 1, 2, 3.

The current firmware runs this work in CAN1_RX0_IRQHandler, not a slow polling task. It copies each accepted frame to g_can1_rx_latest, increments count, then releases FIFO0. When several matching frames arrive quickly, the newest is retained; use a queue/ring buffer if every frame matters.

9. Connect the RX interrupt correctly

Three things are required. Missing any one means frames can sit in FIFO0 without reaching your code.

  1. Set CAN1->IER |= CAN_IER_FMPIE0 to request an interrupt when FIFO0 becomes non-empty.
  2. Set the NVIC priority and enable CAN1_RX0_IRQn.
  3. Put CAN1_RX0_IRQHandler in the startup vector slot for IRQ 20. This repository’s startup file now does that.
CAN1->IER |= CAN_IER_FMPIE0;
NVIC_SetPriority(CAN1_RX0_IRQn, 6U);
NVIC_EnableIRQ(CAN1_RX0_IRQn);

void CAN1_RX0_IRQHandler(void) {
    while (CAN1->RF0R & CAN_RF0R_FMP0) {
        /* read RIR/RDTR/RDLR/RDHR; copy to application storage */
        CAN1->RF0R |= CAN_RF0R_RFOM0;
    }
}
The ISR in this project does not call FreeRTOS. If you later call xQueueSendFromISR(), set the interrupt priority to a numerically equal-or-lower urgency than configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY and use the FreeRTOS “FromISR” APIs exclusively.

10. Use the received data in application code

inc/can1.h defines Can1RxFrame, the volatile latest-frame storage, and a coherent-copy function. Do not copy the volatile structure field-by-field yourself: an interrupt can update it during that copy.

#include "can1.h"

static void ApplicationTask(void *argument) {
    Can1RxFrame frame;
    (void)argument;

    for (;;) {
        if (Can1CopyLatestRxFrame(&frame) == 0) {
            // frame.id is 0x321, frame.dlc is 0..8,
            // frame.data[0..frame.dlc-1] is the payload,
            // frame.count increases for each received matching frame.
        }
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

Can1CopyLatestRxFrame() returns -2 until the first matching frame arrives and -1 for a null destination. It uses an update sequence counter, so it retries if the receive interrupt changes the frame mid-copy.

11. Test with the repository USB-CAN tools

The scripts use python-can. Install it once with python3 -m pip install python-can. Adjust the adapter path if it differs from the example.

# Terminal A: watch only what the STM32 accepts (0x321)
python3 canalyzer_tool/read_can.py --channel /dev/cu.usbmodemAAAD204938841 --id 0x321

# Terminal B: prompted for adapter path, bitrate, ID, and payload
python3 canalyzer_tool/send_can.py

# Or send without prompts
python3 canalyzer_tool/send_can.py --channel /dev/cu.usbmodemAAAD204938841 \
    --bitrate 500000 --id 0x321 --data "DE AD BE EF 01 02 03 04"

read_can.py now accepts interface, channel, bitrate, identifier, and extended-frame options. send_can.py validates an 11-bit standard ID by default, accepts up to eight hexadecimal data bytes, and supports an explicit --extended mode.

12. End-to-end bring-up checklist

  1. Build: make clean && make; flash the generated ELF.
  2. Confirm PB9 shows a 500 kbit/s waveform every 250 ms. The demo sends standard data ID 0x123, DLC 8.
  3. Connect a powered, non-standby transceiver and an ACK-capable USB-CAN adapter at 500 kbit/s.
  4. Run the receive tool to observe the STM32’s 0x123 traffic.
  5. Use send_can.py to send 0x321. PD15 toggles for each accepted frame.
  6. In a debugger, inspect g_can1_rx_latest or call Can1CopyLatestRxFrame().
  7. Send another ID, for example 0x322; the count must not change. That proves the hardware filter is active.

15. What to change next

  • Change CAN_RX_STD_ID in src/main.c and rebuild to select another standard data-frame ID.
  • For several received IDs, allocate extra filter banks or replace the latest-frame store with a FreeRTOS queue.
  • For error handling, enable CAN error interrupts and record ESR.
  • For a production transmitter, choose an explicit retry/error policy instead of using the analyzer-oriented NART configuration.
